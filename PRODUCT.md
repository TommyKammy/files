# Product

## Register

product

## Users

Enterprise members, team leads, and security administrators managing shared files at 100TB / 1,000-user scale. They work in the Files workspace all day: browsing folders, uploading, sharing, classifying, reviewing permissions, and auditing activity. The interface is used in Japanese, often with a keyboard, and must stay fast and legible under dense file lists.

## Product Purpose

Files is a Box-replacement file sharing and governance workspace on Cloudflare Workers, D1, R2, Queues, and Workers AI. It exists to make large-scale file operations feel instant while keeping every action permission-aware and auditable. Success means users can find, select, move, share, and govern files without thinking about the infrastructure.

## Brand Personality

Precise, calm, dense. The product should feel like a professional tool that disappears into the task: quiet surfaces, clear hierarchy, restrained indigo accents, and confidence through consistency rather than decoration.

## Anti-references

- Heavy navy enterprise dashboards with glowing blue buttons and large decorative cards.
- Glassmorphism, gradient text, oversized marketing typography, and playful illustrations inside the workspace.
- Low-density layouts that waste vertical space in file lists.
- Inconsistent controls: pill buttons next to square buttons, mixed radii, and multiple accent colors competing for attention.

## Design Principles

1. Chrome recedes; content is the interface. Navigation and toolbars stay quiet so file names, classifications, and states carry the screen.
2. Dense but calm. Compact rows, thin dividers, and restrained type make large folders scannable without feeling cramped.
3. Accent means action or selection. Indigo is reserved for primary actions, current selection, focus, and state indicators.
4. Every state is designed. Hover, focus, selected, disabled, loading, empty, and error must share one vocabulary.
5. Trust signals stay visible. Classification and permission information remain legible without turning the table into a rainbow.

## Accessibility & Inclusion

WCAG 2.1 AA: body text at 4.5:1 or better, large text at 3:1, visible keyboard focus, and no color-only state. Preserve the existing keyboard-first flows, Japanese IME guards, reduced-motion support, and screen-reader labels.
